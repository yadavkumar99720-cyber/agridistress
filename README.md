# AgriDistress - Farmer Distress Risk Predictor

This project predicts the "risk level" (Low / Medium / High) of farmer
distress in a district based on factors like rainfall, crop yield, debt,
MSP gap, insurance coverage, and crop failure percentage.

## Files

- `agri_distress_dataset.csv` - the dataset (3000 rows)
- `train_model.py` - trains 6 different models, compares their accuracy,
  picks the best one, and saves it along with some graphs
- `app.py` - the Streamlit web app (prediction page + model performance page)
- `model.pkl`, `scaler.pkl`, `encoders.pkl` - saved by train_model.py
- `model_results.csv` - accuracy of every model that was tried
- `best_model_name.txt` - name of the model that scored highest
- `plots/` - graphs generated by train_model.py
- `requirements.txt` - python packages needed

## How to run

1. Install the requirements:

   pip install -r requirements.txt

2. (Optional) Re-train the models and regenerate the graphs:

   python train_model.py

   This will print the accuracy of each model in the terminal and save
   new files: model.pkl, scaler.pkl, encoders.pkl, model_results.csv,
   best_model_name.txt and the plots/ folder.

3. Run the app:

   streamlit run app.py

   Open the link it gives you (usually http://localhost:8501).
   - "Predict Risk" page: enter the details and click Predict.
   - "Model Performance" page: see the accuracy table, bar chart,
     confusion matrix and feature importance graph.

## Models compared in train_model.py

- Logistic Regression
- Decision Tree
- Random Forest
- K-Nearest Neighbors (KNN)
- Support Vector Machine (SVM)
- Gradient Boosting

The model with the highest accuracy on the test set is automatically
selected and saved as model.pkl, so app.py always uses the best one.

## Note about the dataset

While checking the data, the suicide_count column lines up almost
exactly with the risk_level column (Low <= 40, Medium 41-92, High >= 93).
Because of this, several models reach very high (even 100%) accuracy,
mainly because suicide_count alone is enough to predict risk_level. If
you want the model to depend more on the other factors (rainfall, debt,
MSP gap, etc.), consider removing suicide_count from feature_cols in
train_model.py, or collecting risk_level labels that are based on a mix
of factors rather than suicide_count alone.
